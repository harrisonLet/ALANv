What you are looking at

      
    
        
  1. Your code is compiled exactly as for the boat. Build & start compiles the CM7 firmware in
          CM7/ and Common/ with the same Arm compiler and CMake as ./build.sh cm7 -b.
          The only difference is which sensors are switched on (passed as compiler flags, so
          shared_configuration.h is untouched).
    2. 
        
  2. Renode runs that machine code on a virtual STM32H755. It executes the same .elf file you would
          flash, instruction by instruction: HAL, FreeRTOS, your tasks, your interrupts. The firmware card on the right shows
          the branch, commit and edited files it was built from.
    3. 
        
  3. Virtual sensors answer on the real buses. The BNO055 and AS5600 answer I2C register reads, the wind vane
          answers Modbus on UART4, the GPS sends NMEA on UART7. Your drivers run unmodified.
    4. 
        
  4. Your servo commands move a virtual boat. Every 20 ms the simulator reads the PWM your firmware writes to
          TIM1, moves the rudder and tail, and computes the wind, water, wing, keel and heel. The new heading, wing angle,
          wind and position go back into the sensors. That is the loop: your code → servos → boat → sensors → your code.
    5. 
        
  5. The boat is your CAD. Hull, keel, wing, tail and rudder come from the Onshape exports; mass and centre of
          gravity from Onshape plus the counterweight (Stability tab). Areas, positions and buoyancy are measured from the meshes.
    6. 
      

      
Typical loop

      
    
        
  1. Edit firmware in CM7/App/Src.
    2. 
        
  2. Click Build & start. If the build fails, the System log tab says why.
    3. 
        
  3. Watch the boat, the charts and the Firmware console (your printf output). Change wind, current, faults.
    4. 
        
  4. When it behaves, flash the real board from the same code: ./build.sh cm7 -b -f.
    5. 
      

      
Not simulated

      
The CM4 core and LoRa radio; waves (visual only); the physics parameters for drag are estimates until measured on the water.
        Use the simulator to get logic right, and the lake to tune gains.
